# Known Limitations — Privacy Gateway AI

1. **Probabilistic Detection for Unstructured Entities:** While structured Indian identifiers (Aadhaar with Verhoeff checksum, PAN, GSTIN with Mod-36 checksum, IFSC, Email) achieve high deterministic precision/recall, unstructured entities (`PERSON` names in rare/regional transliterations, `ADDRESS` fragments without clear landmarks/PIN codes, and heavily code-mixed Hinglish text) remain inherently probabilistic. We do not claim mathematically guaranteed zero leakage on arbitrary unseen text.
2. **DPDP Compliance Scope:** Privacy Gateway AI provides technical safeguards (pseudonymization, purpose limitation, access control, audit evidence) aligned with the Digital Personal Data Protection (DPDP) Act, 2023 and DPDP Rules, 2025. Using this software alone does not automatically confer legal compliance; organizational governance, consent management, and legal review remain required.
3. **Synchronous Request Scope:** The current release focuses on synchronous request-response document processing (`POST /api/v1/process`). Multi-chunk SSE streaming rehydration and binary OCR document ingestion are architected for future phases and not implemented in the current MVP.
4. **Placeholder Visibility to LLM:** Because typed placeholders (e.g., `<PERSON_SB2N8F>`) are sent to the external LLM, the external model learns entity *types* and *co-occurrence structure* (pseudonymization), though not the underlying personal values.
5. **Newly Generated Hallucinated PII:** If an external LLM hallucinates new PII that was never in the original document, the response scanner flags it rather than attempting restoration.
6. **External Provider Availability & Secondary Provider Verification:** Live integration was verified against Google Gemini's Interactions API (`store=False`, `Api-Revision: 2026-05-20`). During verification, `gemini-3.8-flash` returned transient HTTP `503` ("experiencing high demand") and triggered automatic failover to `gemini-3.5-flash-lite` (HTTP `200`, `10/10` placeholders preserved and restored). OpenAI (`OpenAIAdapter`) remains unverified live because `OPENAI_API_KEY` is not configured in `.env`.
7. **Windows Host Port `5432` Collision:** When native Windows PostgreSQL is installed and listening on `0.0.0.0:5432`, running host-side CLI tools against `127.0.0.1:5432` will hit native Windows PostgreSQL rather than Docker container `pgw-postgres`. Inside Docker Compose (`pgw-backend` -> `postgres:5432`), PostgreSQL connectivity and Alembic migrations execute cleanly without conflict.
