# Competitive Gap Analysis — Privacy Gateway AI

| Capability Area | Existing Market / Open-Source Tools | Standard Today | Privacy Gateway AI Implementation | How We Measure Improvement |
|---|---|---|---|---|
| **Indian Identity Detection** | Presidio has basic global regexes; MaskFlow supports Indian PAN/Aadhaar/GSTIN; Protecto/Skyflow focus mainly on US/EU PII out-of-the-box | Regex + basic spaCy NER | Presidio + custom Verhoeff (Aadhaar), Mod-36 (GSTIN), PAN 4th-char entity code, Voter ID, Passport, Indian address/name context + optional GLiNER NER | Entity-wise Precision, Recall, F1 on our 50-doc Indian enterprise benchmark (`loan`, `kyc`, `support`, `insurance`) |
| **Outbound Boundary Verification** | LiteLLM / ctxproxy / Cloudflare AI Gateway scan input text before routing; some buffer streams | Pre-routing text scan | Independent **Outbound Security Enforcement Engine** inspecting the **final serialized provider JSON payload** with cryptographic ticket binding and `PASS`/`FAIL`/`UNKNOWN` fail-closed blocking | 100% block rate on deliberately tampered post-masking payloads & injected secret/PII negative tests; zero observed outbound leakage |
| **Vault & Token Security** | Many OSS proxies use predictable sequential counters (`<PERSON_1>`) in plaintext Redis | Plaintext Redis sequential tokens | AES-256-GCM encrypted Redis vault with AAD binding `(org_id, request_id, placeholder)`, separate key management, 6-char CSPRNG tokens, collision detection, and short TTL | Unit & security tests verifying ciphertext in Redis, cross-tenant rejection, expired-TTL rejection, and forged-token rejection |
| **Authorized Restoration** | Most gateways automatically unmask for any caller who submitted the prompt | Unconditional auto-unmask | **Identity- & purpose-aware restoration**: submitting a document does not grant unmask permission; RBAC separates `submit` vs `restore` privileges | Security test matrix verifying `developer`/`analyst` without restore scope cannot unmask raw PII |
| **Response Safety & Resilience** | Basic string replace on placeholders; limited handling of LLM hallucinations or forged tokens | Naive `.replace()` | Exact token validation categorizing `restored`, `missing`, `unknown/forged` + post-restoration scan for newly generated PII + no fuzzy guessing | Reinsertion accuracy benchmark across reordered, repeated, paraphrased, dropped, and forged-token LLM responses |
| **DPDP Governance & Evidence** | Commercial DLP tools export generic logs; OSS proxies often lack structured compliance evidence | Raw request logs (risking PII in logs!) | Zero-raw-PII PostgreSQL audit trail capturing detected entity counts, policy version, sanitized payload SHA-256, security gate decision, provider used, and JSON/CSV DPDP evidence export | Automated log/DB audit assertion confirming zero raw PII strings appear in logs or audit tables |

*Note: Commercial capability summaries reflect publicly documented architectures of Protecto, Skyflow, Nightfall AI, Lakera, Lasso Security, Cloudflare AI Gateway, Kong AI Gateway, and LiteLLM as of research review; we claim superiority only in measured Indian-enterprise benchmark performance, fail-closed boundary enforcement, and verifiable auditability.*
